# 软件测试工作台（report-demo）项目说明

## 一、项目名称

- **仓库名**：`report-demo` —— report 代表"测试报告/报表"这条主业务线，demo 表明它是完整可运行的示例工程
- **中文名**：软件测试工作台 —— 定位是"测试工程师的日常工具箱"，不是单一页面，是一套小工具集

## 二、项目定位与作用

**解决什么问题**：测试日常最繁琐的几件事——执行结果靠手算通过率、用例散在 Excel、指标（覆盖率/缺陷密度）要套公式、缺陷没归口、周报报告每次手工拼。这套工作台把这些高频动作全部收拢成一个可交互的工具链。

**给谁用**：测试工程师自己（日常干活）、面试官/HR（展示工程能力）。

**核心价值**：

1. **输入即计算**：粘贴结果文本秒出统计，改一个数字全部指标联动刷新，不用点任何"提交"
2. **数据留存**：用例、Bug、环境、配额配置全存 localStorage，关页面不丢
3. **一键出报告**：所有模块的数据汇总成 Markdown 测试报告，可下载可打印
4. **零门槛运行**：原生 HTML/JS/CSS，无框架无依赖，双击即用，任何环境都能跑

**对外展示亮点**：12 个功能模块覆盖一条完整测试工作流（录入→设计→执行→分析→跟踪→报告）；配额管理复刻了生产级系统的"配置→校验→拦截→统计"完整链路；纯 SVG 手绘图表，不引图表库，代码可完整审查——这些在简历/面试里都是能讲故事的点。

## 三、设计思路（7 条主线）

**1. 场景驱动拆模块**：先想"测试同学一天都干嘛"——录结果、写用例、算指标、跟 Bug、排计划、查环境、出报告，于是有了 12 个页面，每个页面只干一件事，组合起来就是完整工作流。

**2. 数据层与展示层分离**：所有页面共享一个 `data.js` 里的 Store 单例，统一读写 + localStorage 持久化；页面逻辑只负责"读数据→算→渲染"，改数据源（比如接 pytest 导出）不影响任何页面。

**3. 图表自绘**：bar/line/pareto 三种图全用 SVG 手写，不引 ECharts/Chart.js。理由：一是零依赖可双击运行，二是展示真实的 DOM/SVG 功底，三是在线审查时代码量可观、可读。

**4. 输入即计算**：每个输入框都绑实时事件，没有"提交-等待-刷新"的滞后感——这是工具类产品的核心体验，也是"能交互能计算"的硬要求。

**5. 数据流转闭环**：录入台解析的结果可一键存入用例库 → 用例管理 → 指标/缺陷/趋势 → 报告导出汇总全部模块，数据在一套系统里流动，不是孤岛。

**6. 复刻生产系统链路**：配额管理按真实系统的设计思路做成完整闭环——配额配置（可编辑限额）→ 操作发生时校验（用量+本次操作 vs 限额）→ 超限拦截（拒绝并提示）→ 用量统计（进度条+正常/预警/超限状态）→ 操作日志（放行/拦截全记录）。用量还联动工作台真实数据（用例数、Bug 数、环境数自动算）。

**7. 分层扩展性**：`data.js`（数据）/ `charts.js`（绘图）/ `nav.js`（导航）/ 每页独立逻辑 JS —— 加一个新模块 = 加一个 HTML + 一个 JS + 数据层加一块，不动其他任何文件。

## 四、模块关系与数据流

```
数据录入台 ──保存──▶ 用例管理 ◀──筛选/搜索/状态
   │                    │
   ▼                    ▼
实时统计/模块分布      指标计算器（通过率/覆盖率/缺陷密度…）
                        │
缺陷分析（Pareto）◀────┤
Bug 管理 ──────────────┤──▶ 报告导出（Markdown 汇总）
测试计划 ──────────────┤
趋势分析 ──────────────┘
接口用例库 ──导出──▶ Postman 集合
环境管理 ──┬─▶ 配额管理（用量取真实数据：用例/Bug/环境）
配额管理 ──┘   （配置→校验→拦截→统计）
```

## 六、瑕疵埋雷位置（2 个主动埋 + 8 个天然存在，全部低风险、不破坏主流程）

| #    | 文件            | 位置                                           | 表现                                                         |
| ---- | --------------- | ---------------------------------------------- | ------------------------------------------------------------ |
| 1    | `cases.js`      | `init()` 新增用例 handler                      | **主动埋**：只清空"名称"框，模块/要点残留，连点会把上一条带进下一条 |
| 2    | `quota.js`      | `q-run` handler，`inc = op === "file" ? 2 : 1` | **主动埋**：页面写"上传文件(1MB)"，实际每次扣 2MB            |
| 3    | `report.js`     | `buildReport()` 里 `new Date().toISOString()`  | 生成日期用 UTC，晚上 8 点后报告日期显示成前一天              |
| 4    | `bugs.js`       | `SEV` 映射表                                   | 严重程度"一般"→ 绿色标签（跟"通过"同色），色板偷懒           |
| 5    | `report.js`     | `## 五、后续计划`                              | 两条计划写死硬编码，不接真实数据                             |
| 6    | `api.js`        | `buildPostmanCollection()`                     | `_postman_id` 写死固定值；路径带 `?query` 会解析不准         |
| 7    | `calculator.js` | `save` handler                                 | 保存到用例库不查重，重复粘贴重复入库                         |
| 8    | `defects.js`    | `updateAnalysis()` 末尾                        | Pareto 图传未排序的 `items`（内部排序兜底，结果对，但代码看着像漏了一步） |
| 9    | `plan.js`       | `pl-add` handler                               | 创建计划后表单不清空，连建会带上次输入                       |
| 10   | `quota.js`      | `q-run` handler 上方                           | `inc` 是废话三元（现在 `? 2 : 1` 依然是冗余写法）            |
